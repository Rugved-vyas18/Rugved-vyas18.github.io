01

RAG + verification · 2026 · solo build

GlassBox

A RAG engine that cites every claim, or refuses to answer at all.

A question-answering engine for anti-money-laundering rules in the US, EU and Brazil. It splits every answer into individual claims, checks each one against the passage it cites, removes what isn’t supported, and when the evidence is too weak it refuses and hands the question to a person.

Method

How I work

Four rules. The first came from citrus detection on real orchard images; the rest are how GlassBox is built.

  1. 01

    Find the failure cases first

    A detector that scored well on clean data broke on real orchard images. I start from the data and where it fails, not from a bigger model.

    Citrus detection
  2. 02

    Ground every answer

    Retrieval with query expansion, and a knowledge graph that notices a missing jurisdiction and goes back for it.

    GlassBox · Retrieve, Ground
  3. 03

    Verify each claim

    Every sentence is split into claims and checked against the passage it cites. Unsupported claims are removed before anyone reads them.

    GlassBox · Verify
  4. 04

    Refuse when evidence is weak

    Below the threshold the system abstains and routes the question to a person. A refusal is a correct answer.

    GlassBox · Decide

Then ship it. FastAPI services, Docker, and tests that run offline: 38 of them for GlassBox.
